## Trust boundaries and limitations

Evidence signatures authenticate content and the approved signing key; they do not prove the collector, operating system, source data, operator or clock was honest. A signer with key access can sign arbitrary data. PowerShell callers can construct in-memory objects: `InMemory` explicitly does not authenticate provenance. Use `-RequireSignedBaseline` and load through `Read-PatchSnapshot` for an audit workflow. Never use a JSON `EvidenceVerification` property as authority. A module reload loses its in-memory verification registry; reload the signed baseline through the module.

The envelope contains the signing certificate, never its private key. Only RSA >=2048 and SHA-256 are supported. Trust is an explicit certificate-thumbprint allowlist (thumbprints are identifiers; signatures use SHA-256), not automatic trust of embedded certificates or automatic PKI chain/revocation validation. Signers must be within their current validity period. There is no trusted timestamp or historical-signature validation. Remove compromised/revoked pins promptly; retain original evidence and manage expiration/rotation with your audit team. Offline verification cannot discover revocation automatically. Private keys and the pin policy must be protected independently of evidence.

`Read-PatchReport` authenticates the recorded report when its signer is trusted; it does not perform a new live collection. Unsigned reports return Review with the original claimed verdict retained separately. Invalid CMS never falls back to unsigned parsing. A signed Review report remains Review. Signed evidence is not encrypted and does not prevent deletion, rollback or replay; retention controls and maintenance records must establish which baseline belongs to which change window.

Authenticode is evaluated by Windows on the collecting target, using its trust/network policy. `Status=Valid` can be valid with a currently expired signer certificate when a trusted timestamp applies; `CertificateTimeValid` is reported separately. Capture the timestamp signer, but this app does not implement its own chain or revocation engine. A trusted publisher is not proof of a vulnerability fix. Exact subject policy does not pin a specific executable signing certificate.

No patch installation, service control, firewall/WinRM/TrustedHosts modification, Defender configuration change, credential delegation or external dependency was added. Domain Admin and CredSSP are unnecessary. Service/application health, every product component and CVE/KB remediation remain outside this tool's claims.
